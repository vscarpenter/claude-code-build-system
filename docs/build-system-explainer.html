trust boundary · split authority

Credentials stop where creativity begins.

The most capable process has the least authority. The process with GitHub credentials performs no creative work. Capability and custody deliberately move in opposite directions.

01 / untrusted input

Contract + repository

Issue text, branch contents, dependencies, and model suggestions can all be adversarial.

  • No implicit trust from labels
  • No trust from branch prefix
  • No trust from model prose

02 / deterministic boundary

Controller

Owns the lease, worktree, digests, GitHub transport, verification, and evidence.

  • Rechecks before mutation
  • Fails closed on unknown
  • Observes exact SHAs

03 / bounded worker

Claude adapter

Read, Edit, Write, Glob, Grep. No Bash. No GitHub token. Structured JSON only.

  • Plan or ordinary edits
  • Cannot author delivery
  • Cannot certify verification

OS isolation still requires a container or VM.

Failure is a state, not a surprise.

Inject a fault. The record changes, the recovery path becomes explicit, and the worker never gains a delivery route.

Code proves the mechanism. Production proves the boundary.

Release readiness is a set of observed facts, not an optimistic label. The final test uses the real repository, the real harness, and the real automation identity.

node scripts/build-system.cjs doctor --harness all
  1. Doctor reports READY against the intended repository.
  2. Real harness issue-to-PR smoke succeeds.
  3. Actual credential cannot direct-push, force-push, or merge.
  4. Required checks exist and are enforced on the default branch.
